### PR Description

## Summary
- Use `torch::stable::accelerator::getCurrentStream(...).nativeHandle()` in `deep_jit::ascend::Kernel::launch` when building against PyTorch 2.13+ (`TORCH_FEATURE_VERSION >= TORCH_VERSION_2_13_0`), eliminating the compile-time `<torch_npu/csrc/core/npu/NPUStream.h>` header and link-time `-ltorch_npu` requirement for stable-ABI (`abi3`) consumers.
- Preserve the `c10_npu::getCurrentNPUStream()` fallback when `TORCH_FEATURE_VERSION < TORCH_VERSION_2_13_0`.
- Update `tests/test_ascend.py` to omit `torch_npu` C++ include/library paths on PyTorch 2.13+ so header self-containment and runtime tests actively verify zero `libtorch_npu.so` link dependency.

## Test Plan
- Ran full `python tests/test_ascend.py` on Ascend 950 (`dav-3510`, CANN 9.3, PyTorch 2.13) — all 28 self-contained headers, AICPU bootstrap, SIMD/SIMT, multiprocess compilation, and default-stream launches pass without `-ltorch_npu`.
