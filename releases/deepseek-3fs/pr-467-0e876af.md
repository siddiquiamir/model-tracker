### PR Description

## Summary

Reject syncing updates that do not start at offset 0 (`is_syncing && offset != 0`).

## Root Cause

A syncing write replaces the whole chunk and carries a checksum over the full payload. `copy_on_write`'s skip-read path stores that caller-provided checksum directly as the new chunk checksum without reading or covering the bytes before `offset`. If such a request reached the engine with `offset > 0`, the persisted metadata would describe a checksum that does not match the actual slot content.

The forwarding path normally rewrites syncing payloads to `offset = 0`, and `StorageOperator` already rejects syncing truncate/extend requests, so this is a defensive guard rather than a known remote-triggerable bug.

## Changes

- `src/storage/chunk_engine/src/core/engine.rs`
  - Reject `is_syncing && offset != 0` at the top of `Engine::update_chunk` with `Error::InvalidArg`.
  - Add `test_engine_rejects_syncing_write_with_nonzero_offset`, which also checks that a syncing write at offset 0 still succeeds.

## Compatibility

Request-validation only; normal syncing writes use offset 0 and are unaffected. No on-disk format change.
