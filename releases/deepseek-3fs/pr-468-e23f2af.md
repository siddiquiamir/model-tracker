### PR Description

## Summary

Fixes two data-path bugs in `Chunk::copy_on_write` and `Chunk::safe_write` in `src/storage/chunk_engine/src/alloc/chunk.rs`:

1. **Syncing overwrites allocate based on the old chunk length instead of the incoming payload length.**
   In `Chunk::copy_on_write`, `new_len` was computed as `std::cmp::max(self.meta.len, offset + data.len() as u32)` even when `is_syncing` is `true`, and `new_chunk.meta.len` was only narrowed back to `offset + data.len() as u32` at the end. When replication/sync (`ReliableForwarding` -> `is_syncing = true, offset = 0`) replaces a larger chunk (e.g. 256 KiB / 512 KiB) with a smaller or empty payload:
   - The replacement slot is allocated from the old oversized size class instead of the target size class, wasting disk capacity and skewing `used_size` accounting (and failing unnecessarily with `NoSpace` when the old larger size class is full while the smaller target class still has free slots).
   - For a zero-length syncing overwrite (`data.is_empty()`), `new_len` stayed equal to `self.meta.len`, causing `copy_on_write` to flush `self.meta.len.next_multiple_of(ALIGN_SIZE)` bytes of stale thread-local `Chunk::BUFFER` contents to disk via `pwrite` even though the resulting chunk length is 0.
   - If `truncate` happened to be set alongside `is_syncing` and `data.is_empty()`, `is_shrinking` was also incorrectly triggered and incremented `safe_write_truncate_shorten`.

2. **Unaligned buffered writes flush stale thread-local `Chunk::BUFFER` bytes into the aligned tail on disk.**
   Both `Chunk::copy_on_write` (non-shrinking buffered writes) and `Chunk::safe_write` (indirect append path) round the `O_DIRECT` write length up to `ALIGN_SIZE` (4096 bytes) using the shared thread-local `Chunk::BUFFER`, without zeroing `vec[new_len..aligned_end]`. Bytes left behind in `Chunk::BUFFER` by previous operations on unrelated chunks were written out to disk in the aligned tail block (whereas shrinking truncates already zeroed `vec[new_len..len]`).

## Fix

- In `Chunk::copy_on_write`:
  - Exclude `is_syncing` from `is_shrinking` and compute `new_len = offset + data.len() as u32` when `is_syncing` is `true`, so both allocation size and `pwrite` length match the replacement payload (and skip `pwrite` entirely when `new_len == 0`).
  - Always zero `vec[new_len as usize..len as usize]` before `new_chunk.pwrite` on the buffered path.
  - Simplify `new_chunk.meta.len = new_len`.
- In `Chunk::safe_write` (indirect append path):
  - Compute `aligned_end = new_len.next_multiple_of(ALIGN_SIZE.into())` and zero `vec[new_len..aligned_end]` before `self.pwrite`.
